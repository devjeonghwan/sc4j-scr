# SCRECBIN 버전 0.1 와이어 형식

[English](sc-recorder-format.md) | **한국어**

SCRECBIN은 프레임 기록기 `sc-recorder`(`sc-recorder/`)의 바이너리 파일 형식입니다. 게임의 관찰된 상태를 프레임마다 타입이 있는 샘플로 기록합니다. 이 문서는 파일 구조, 샘플, 캡처 규칙, 읽는 쪽이 확인하는 한계를 설명합니다.

## 범위

SCRECBIN 0.1은 타입이 있는 전체 스냅숏을 저장합니다. 다른 버전과 텍스트 SCREC 파일은 읽지 않습니다.

모든 숫자 필드는 리틀엔디언입니다. 파일 형식 버전이 모든 샘플 페이로드 계약을 정합니다. 샘플 식별자는 소스에 정의된 읽기와 쓰기 코드를 고르며, 파일에는 필드 목록, 클래스 이름, 스키마 식, 샘플별 버전이 없습니다.

## 파일 구조

```text
Fixed header
Selected sample identifiers
Typed provenance metadata
FRAME chunk, sequence 0
FRAME chunk, sequence 1
...
END chunk, next sequence
Physical EOF
```

선택한 식별자는 양수이고, 중복이 없고, 엄격하게 증가합니다. 각 프레임에는 선택한 식별자마다 정확히 하나의 관찰이 같은 순서로 들어 있습니다.

## 고정 헤더: 32바이트

| 오프셋 | 폭 | 의미                |
|--------|----|---------------------|
| 0      | 8  | ASCII SCRECBIN      |
| 8      | 2  | major = 0           |
| 10     | 2  | minor = 1           |
| 12     | 4  | totalHeaderBytes    |
| 16     | 4  | featureFlags = 0    |
| 20     | 4  | selectedSampleCount |
| 24     | 4  | metadataBytes       |
| 28     | 4  | header CRC32C       |

고정 헤더 다음에 selectedSampleCount개의 부호 없는 32비트 식별자, 그다음 정확히 metadataBytes 바이트의 메타데이터가 옵니다. 패딩은 없습니다.

```text
totalHeaderBytes = 32 + 4 * selectedSampleCount + metadataBytes
```

헤더 CRC32C는 바이트 28..31을 0으로 둔 헤더 전체를 대상으로 합니다. 읽는 쪽은 Record를 만들기 전에 크기, 체크섬, 알려진 식별자, 순서를 검증합니다.

## 타입 메타데이터

각 항목은 tag u16, flags u16, payloadBytes u32와 페이로드 바이트로 이루어집니다. 플래그 비트 0은 REQUIRED입니다. 알려진 태그가 중복되면 실패합니다. 모르는 선택 태그는 한계 안에서 건너뛰고, 모르는 필수 태그는 실패합니다.

| 태그 | 페이로드                                                   |
|------|------------------------------------------------------------|
| 1    | 생성기 버전, strict UTF-8                                  |
| 2    | 실행 파일 SHA-256, 32바이트                                |
| 3    | 요청한 리플레이 SHA-256, 32바이트                          |
| 4    | 불러온 리플레이 근거, u8                                   |
| 5    | 샘플링 방식, u16                                           |
| 6    | 폴링 간격(나노초), u64                                     |
| 7    | 커버리지 요구 사항, u32                                    |
| 8    | 허용하는 다이제스트 알고리즘, u16: 1 = SHA-256             |
| 9    | 예상 첫/마지막 프레임, u64 값 둘. 모든 비트 1은 알 수 없음 |

불러온 리플레이 근거: 0 사용할 수 없음, 1 불러온 헤더 일치, 2 불일치. 헤더가 같다고 리플레이 바이트 전체가 같은 것은 아닙니다. 샘플링 방식: 0 호출자가 준 값, 1 읽기 전용 외부 마커 폴링. 출처 정보가 없다고 해서 검증된 캡처라는 뜻은 아닙니다.

## 청크 헤더: 24바이트

| 오프셋 | 폭 | 의미                        |
|--------|----|-----------------------------|
| 0      | 2  | kind: 1 FRAME, 2 END        |
| 2      | 2  | chunkFlags = 0              |
| 4      | 4  | payloadBytes                |
| 8      | 8  | sequence, 0부터 시작        |
| 16     | 4  | chunk CRC32C                |
| 20     | 4  | reserved = 0                |

CRC32C는 바이트 0..15, 바이트 20..23, 페이로드 전체를 이 순서로 대상으로 합니다. 체크섬 필드는 빠집니다. 읽는 쪽은 디코딩 전에 한계, 시퀀스, 체크섬을 검증합니다. CRC는 우발적인 손상을 찾아낼 뿐, 진위를 보증하지 않습니다.

## FRAME 페이로드

24바이트 앞부분에는 observedFrame u64, elapsedNanoseconds u64, sampleCount u32, consistency u32가 있습니다.

consistency: 0 UNVERIFIED, 1 MARKER_STABLE, 2 TORN. 프레임 번호는 엄격하게 증가하지만 빈틈이 있을 수 있습니다. 경과 시간은 스테이징을 시작할 때 잽니다. MARKER_STABLE은 마커 확인이 성공했다는 뜻이지 원자적 스냅숏이라는 뜻은 아닙니다.

각 샘플에는 18바이트 헤더가 있습니다.

| 폭 | 의미                                                        |
|----|-------------------------------------------------------------|
| 4  | sampleIdentifier                                            |
| 1  | storageMode: 0 VALUES, 1 DIGEST, 2 NONE                     |
| 1  | status: 0 AVAILABLE, 1 READ_FAILED, 2 TORN, 3 NOT_ATTEMPTED |
| 8  | sampledFrame. 사용할 수 없으면 모든 비트 1                  |
| 4  | payloadBytes                                                |

사용할 수 없는 관찰에는 NONE, 페이로드 없음, 샘플 프레임 없음이 필요합니다. 사용할 수 있는 관찰에는 VALUES나 DIGEST, 그리고 observedFrame보다 늦지 않은 음이 아닌 샘플 프레임이 필요합니다. 구역 사이에 패딩은 없습니다.

### VALUES 페이로드

구체적인 `SampleDefinition`마다 한계가 있는 `SampleReader`와 정규형 `SampleWriter`를 제공합니다. 그 `getEncodedSize` 메서드는 쓰기 전에 재사용할 저장 공간을 확보합니다. 읽기와 쓰기는 선언된 페이로드를 정확히 다 소비해야 합니다.

| 식별자 | 이름            | 모델                 |
|--------|-----------------|----------------------|
| 1      | players         | PlayersSample        |
| 2      | units           | UnitsSample          |
| 3      | random          | RandomSample         |
| 4      | frame           | FrameStateSample     |
| 5      | random-counters | RandomCountersSample |
| 6      | locations       | LocationsSample      |
| 7      | lists           | UnitListsSample      |
| 8      | context         | ContextSample        |
| 9      | triggers        | TriggersSample       |
| 10     | eud             | EudSample            |
| 11     | eud-hosts       | EudHostsSample       |
| 12     | ai              | AiSample             |
| 13     | camera          | CameraSample         |
| 14     | sync            | SyncSample           |
| 15     | tiles           | TilesSample          |
| 16     | runtime-random  | RuntimeRandomSample  |

각 샘플 패키지의 명시적인 읽기/쓰기 소스가 필드 순서, 정수 폭, 선택 값 플래그, 컬렉션 한계를 정합니다. 페이로드를 바꾸려면 파일 형식을 개정해야 합니다.

플레이어와 유닛 테이블은 식별자를 키로 하고 그 순서로 정렬합니다. 유닛 식별자는 원본 풀 슬롯이며, 대상 포인터는 슬롯으로 바꿉니다. 로케이션 항목은 식별자 순서입니다. EUD 영역 항목은 가상 키 순서입니다. 보이는/숨은 유닛 목록은 원본 순회 순서를 유지합니다. 순서가 관찰된 상태의 일부이기 때문입니다.

프로세스 주소는 인코딩 전에 정규화하므로, 같은 게임 상태는 다른 프로세스에서도 같은 페이로드를 줍니다.

- units: 유닛 +0x128의 클래스 종속 공용체는 유닛 타입에 따라 종류 바이트와 u64 값으로 디코딩합니다. 일꾼(SCV, Drone, Probe), Nuclear Silo, Nydus Canal은 유닛 포인터를 가지며 풀 슬롯으로 저장합니다(종류 1. 포인터가 풀 슬롯을 가리키지 않으면 모든 비트 1. SC4J도 거부하는 리플레이에서 관찰됨). 핵 시전자(Ghost와 그 영웅)와 Pylon은 유닛 풀 밖의 포인터(핵 점, 사이 필드 스프라이트)를 가지며 존재 여부 0 또는 1로 저장합니다(종류 2). 그 밖의 타입은 원래 워드 넷을 유지합니다(종류 0).
- context: 불러온 맵이나 리플레이 경로(+0xC4C, 260바이트. 기록기의 세션 폴더 이름이 들어 있음)와 화면 타일(+0xE0, 4바이트)을 0으로 둡니다.
- ai: 영역 테이블 포인터는 존재 여부 0 또는 1이 됩니다. +32, +40, +56의 영역 행 포인터는 유닛 풀 기준 오프셋(같은 게임 아레나)이 되고, +64와 +72의 것은 모듈 베이스 기준 오프셋이 됩니다. 유닛 AI 레코드 주소는 모듈 베이스 기준 오프셋이 됩니다.
- sync: 0x140E76B70의 256바이트 그리기 순서 버킷 테이블(그리기 단계가 쓰는 렌더 작업 공간)은 기록하지 않습니다. 블록은 0x140E76C70에서 시작하며, 첫 QWORD인 게임 아레나 포인터는 유닛 풀 기준 오프셋이 됩니다.
- tiles: 맵 너비와 높이(각 u16, 게임 컨텍스트 +0xE4와 +0xE6), 그다음 너비 * 높이 개의 타일 식별자 WORD를 행 우선 순서로, 맵 너비를 행 길이로 하여 0x140E7E478의 포인터가 가리키는 타일 배열(크립 루틴이 바꾸는 배열)의 시작부터 읽습니다. 배열 포인터 자체는 기록하지 않습니다.
- runtime-random: u32 행 수, 그다음 행마다 스레드 순서 u16과 C 런타임 난수 상태 u32(런타임 스레드 데이터 +0x28의 `rand`/`srand` 상태). 스레드 식별자와 주소는 프로세스 로컬이므로, 행은 스레드를 순서로 밝힙니다. 최근 목록의 대상 스레드 중 생성 시각에 따른 순위이며 (스레드 목록은 이 샘플을 위해서만 만듦), 처음 스레드는 0입니다. 스레드 데이터는 실행 파일이 0x140E09508에 두는 인덱스의 fiber local storage 슬롯을 통해 찾습니다(TEB +0x17C8, 그다음 슬롯 청크 테이블). 블록은 첫 포인터가 실행 파일의 예외 동작 테이블 0x140C38280을 가리키는 동안만 유지하며, 샘플은 다른 것을 읽느니 실패합니다. 블록을 더는 읽을 수 없거나 슬롯이 더는 그 블록을 가리키지 않는 스레드는 종료된 것입니다. 그 샘플에서 빠지고 다음 샘플을 위해 스레드 목록을 다시 만들며, 그동안 생긴 스레드도 추가합니다. 순서는 최근 목록의 순위이므로, 목록을 다시 만든 뒤에는 종료된 스레드보다 늦게 생긴 스레드의 순서가 하나씩 내려갑니다. 처음 스레드는 순서 0을 유지합니다. 샘플은 목록의 어느 스레드에도 읽을 수 있는 런타임 스레드 데이터가 없을 때, 또는 스레드의 슬롯이 아직 가리키는 블록이 예외 동작 테이블 확인에 실패할 때만 실패합니다.
- eud와 eud-hosts: 에뮬레이터, 가상 테이블, 호스트 포인터, 그리고 객체, 노드, 호스트 헤드 바이트 중 포인터 값인 워드는 2^62 더하기 이미지 오프셋(실행 파일 이미지 안의 포인터) 또는 2^61(그 밖의 포인터, 존재 여부만)이 됩니다. 0은 0으로 남으므로, 에뮬레이터가 없는 게임은 전과 같이 인코딩됩니다.

비교 샘플은 players, units, random, frame, random-counters, locations, lists, triggers, eud, eud-hosts입니다 (`SampleDefinitions.getComparisonDefinitions`). context, ai, camera, sync는 클라이언트, 렌더, 프로세스 로컬 상태를 담고, tiles와 runtime-random은 컴퓨터마다 C 런타임 난수 생성기가 정하는 상태(크립 타일 변형)를 담습니다. 이들은 진단용으로만 기록합니다. camera(시점, 커서, 입력)는 시뮬레이션 비교에 절대 들어가지 않습니다.

EUD 에뮬레이터가 없으면 빈 관찰로 명시적으로 나타냅니다. 0이 아닌데 읽을 수 없는 포인터는 꾸며 낸 바이트를 만들지 않고 캡처를 실패시킵니다. 제공된 값과 타입 2 헤드는 그것을 정의하는 영역 종류에 대해서만 기록합니다. EUD 호스트 메모리 전체의 스냅숏이 아닙니다.

### DIGEST 페이로드: 32바이트

DIGEST는 SHA-256 원본 바이트를 저장합니다. 입력은 다음과 같습니다.

```text
ASCII SCREC-STATE (11 bytes)
formatMajor u16 = 0
formatMinor u16 = 1
sampleIdentifier u32
canonical VALUES payload
```

형식 버전과 식별자가 해시를 구체적인 페이로드 계약에 묶습니다. 해시만 있는 관찰로는 모델을 복원할 수 없습니다. `Frame.getSample`은 명시적으로 실패하고, 그 `SampleObservation`이 다이제스트를 제공합니다.

## 캡처

기록기는 프레임 카운터(게임 컨텍스트 +0x14C)를 바쁜 루프(`Thread.onSpinWait`)로, 또는 `--poll-us N`이면 고정 간격으로 폴링하고, 카운터가 바뀌는 즉시 정착 지연 없이 선택한 프레임을 샘플링합니다. 첫 프레임을 기록하기 전에 모든 샘플러를 한 번 미리 실행합니다. 원본 게임은 프레임 시작(0x140319F38)에서 카운터를 올리며, 그다음 프레임 단계 0x14031C610이 RNG를 켜고 시뮬레이션을 실행합니다. 그래서 한 번의 패스는 그 앞뒤에 읽은 카운터가 같고, RNG 블록(상태, 합계, 게이트)이 바뀌지 않았고, 두 번 읽은 게이트가 모두 꺼져 있을 때만 받아들입니다. 게이트는 프레임 단계가 실행되는 동안 켜져 있습니다. 카운터가 바뀐 패스는 잃습니다(프레임이 빠짐). RNG 앞뒤 확인이 계속 불안정한 패스는 다시 시도하고, 그래도 안 되면 strict 모드에서는 TORN으로 쓰고 tolerant 모드에서는 버립니다.

커버리지 모드: strict(`--coverage strict`, 기본값)는 빈틈 없음, 마커가 안정된 프레임, 예상한 경계를 요구합니다. tolerant (`--coverage tolerant`)는 사용할 수 있는 샘플과 마커가 안정된 프레임만 요구하므로, 놓치거나 버린 프레임은 없는 채로 남습니다. 솎아 내기 (`--dense-frames N --stride K`)는 처음 N개의 모든 프레임, 그다음 K 프레임 주기마다 처음 관찰된 프레임, 마지막 예상 프레임부터의 모든 프레임을 기록합니다. `--frames A..B`는 구간을 기록합니다. 기록하지 않은 프레임은 END의 빠진 범위에 나타납니다. `--preset test`는 비교 샘플, DIGEST 저장, tolerant 커버리지, `--dense-frames 2400 --stride 24`, `--playback-speed X4`를 고릅니다. 게임은 `--launch --noSound`로, 또는 `--sound on`이면 `--launch`만으로 시작합니다. `--playback-speed X1|X2|X4|X8|MAX`는 `--playbackSpeed=...`를 추가합니다.

`validate FILE`은 파일 전체를 읽고, 파일이 올바르고 정상 종료와 함께 커버리지 요구 사항을 만족하면 0, 올바르지만 부분적이면 3, 올바르지 않으면 1로 종료합니다. `inspect FILE`은 메타데이터, 샘플, 프레임 수, 빠진 범위를 출력합니다.

`SampleDigester`는 샘플의 값으로 DIGEST를 계산하며, DIGEST 관찰이 저장하는 것과 정확히 같습니다. 같은 샘플 값을 만드는 프로그램 (시뮬레이션)은 이것으로 다이제스트를 비교합니다.

## END 페이로드

고정 64바이트 앞부분:

| 폭 | 의미                                                    |
|----|---------------------------------------------------------|
| 8  | 확정된 frameCount                                       |
| 8  | 처음 관찰된 프레임. 없으면 모든 비트 1                  |
| 8  | 마지막 관찰된 프레임. 없으면 모든 비트 1                |
| 4  | termination: 0 NORMAL, 1 CANCELLED, 2 TIMEOUT, 3 FAILED |
| 4  | 품질 플래그: 비트 0 요구 사항 만족                      |
| 8  | 빠진 프레임 수                                          |
| 8  | 사용할 수 없는 샘플 수                                  |
| 8  | 찢어진 프레임 수                                        |
| 4  | 빠진 범위 수                                            |
| 4  | reserved = 0                                            |

앞부분 다음에 빠진 프레임의 첫/마지막 쌍이 옵니다(포함 범위 하나에 u64 값 둘). 범위는 정렬되어 있고, 겹치지 않으며, 합쳐져 있습니다. 전체 개수는 선언한 개수와 관찰된 프레임에 맞아야 합니다.

개수, 경과 시간, 프레임 번호는 `0..Long.MAX_VALUE` 안에 들어갑니다. 모든 비트 1 표시값은 명시한 곳에만 씁니다. 포함 범위 계산은 넘치면 안 됩니다.

END는 마지막 청크입니다. `readNextFrame`은 검증된 END와 물리적 EOF 뒤에만 null을 반환합니다. 올바른 END도 빈틈이나 실패한 캡처를 보고할 수 있습니다. 끝나지 않은 쓰기 객체를 닫아도 성공 END는 만들어지지 않습니다. END가 없으면 잘린 입력입니다.

## 한계와 검증

- 헤더: 최대 1 MiB.
- 청크 페이로드: 최대 64 MiB, 할당 전에 확인.
- 선택한 샘플: 1..4096.
- 각 샘플에는 소스에 정의된 신뢰할 수 있는 최대 페이로드 크기가 있습니다.
- 컬렉션 개수, 포인터 범위, 산술은 할당이나 순회 전에 확인합니다.
- CRC, 예약 값, 시퀀스, 식별자, 페이로드를 정확히 다 소비했는지를 검증합니다.
- 모르는 식별자와 지원하지 않는 형식 버전은 실패합니다.
- 입출력 실패는 결함 상태의 쓰기 객체와 구별할 수 있는 부분 출력을 남깁니다.

테스트는 타입이 있는 왕복, 독립적인 다이제스트 벡터, 손상되거나 다시 계산한 CRC 입력, 모르거나 중복된 식별자, 잘못된 개수와 메타데이터, 잘린 입력, END 품질, 물리적 EOF를 다룹니다. 원본 메모리 픽스처는 복원한 캡처 구조와 잘못된 포인터를 다룹니다. 실제 게임에서의 커버리지는 따로 보고합니다. 이 검사들은 손실 없는 폴링이나 큰 파일 성능을 보장하지 않습니다.
